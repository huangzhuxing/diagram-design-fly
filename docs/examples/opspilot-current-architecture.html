01 / RUNTIME

运行时总览

浏览器不会直接操作任何领域对象。所有交互先进入 useSreState：配置了 NEXT_PUBLIC_API_URL 时调用 Go API；未配置或连接失败时，使用前端内置状态机完成可交互演示。

主路径：UI action → API route → domain mutation → Repository → store连续流动仅提示方向；静态与打印版信息完整

Read model

前端以完整工作区状态为主读模型

远程模式通过 GET /api/state 获取整份 domain.State；动作接口只返回局部结果，采集、拉取和经验召回后由客户端再次刷新完整状态。当前没有 WebSocket、SSE 或固定周期轮询。

Important boundary

“离线 Demo”是完整的第二条执行路径

连接失败不会进入只读态，而是由 TypeScript 在浏览器中复制圆桌、采集、信号和经验状态迁移。它适合产品演示，但不是后端行为的一致性证明。

02 / DEPENDENCIES

Go 模块依赖

后端是单进程、单二进制的模块化单体。httpapi.Server 只负责协议适配和错误映射；领域能力拆为包，并通过共享的 repository.Repository 汇聚到同一状态边界。

结构中心：repository.Repository 是最高扇入点9 个包级节点 · 14 条显式依赖

03 / STATE MACHINE

圆桌变更状态机

当前高风险变更控制不是自由对话，而是由后端 roundtable.Service 强制执行的有限状态机。每个写动作都通过 Repository 的单次 Update 闭包完成，非法阶段统一映射为 HTTP 409。

阻断规则：非法阶段、缺少共识或双门禁失败均不会推进状态5 个状态 · 4 个主迁移 · 1 个执行自循环

04 / INTERFACES

接口与数据边界

API 不是按页面组织，而是按运维能力域组织。所有写操作最终都变成对单一 domain.State 的原子进程内变更，再由具体仓储实现提交。

能力域主要接口内部行为与状态
工作区读模型GET /api/state返回 Metrics、Sources、Assets、Relations、Changes、Signals、Alerts、Incidents、Roundtables、Experiences 与 Activity 的完整快照。
CMDB 与变更/api/cmdb/assets · /topology · /collect · /changes采集输入归一化、按 ExternalID 去重；外部变更按关键词和环境分类、提级风险并按 ID 幂等。
信号与事件/api/signals/ingest · /pull · /alerts · /incidents由服务名和信号类别生成指纹；优先抑制重复，其次归并在途事件，仅新的 critical 影响创建事件和告警。
异步 RCAPOST /api/incidents/{id}/analyze进程内 goroutine 启动 analysisTask；两阶段读取变更、拓扑和历史经验，经 Harness 上限约束后更新根因与证据。
知识经验/api/experiences/search · /recall基于标签、中文/英文关键词与置信度打分；Search 只读，Recall 会增加 reused 并写入 Activity。
变更圆桌/advance · /work-order · /approve · /execute四角色独立规则形成全票门禁；工单审批后逐步执行，最后一步关闭工单并新增经验。
05 / DEPLOYMENT & LIMITS

部署方式与当前边界

同一仓库包含两个可独立运行的交付单元：vinext 前端 Worker 与 Go API 容器。Docker Compose 只编排 MongoDB 和 API，前端仍需单独启动或部署。

Runtime topology

当前可运行组合

  • 纯前端 Demonpm run dev；无 API 地址时使用浏览器内 demoState 和 localRoundtableTransition。
  • API + MemorySRE_STORAGE=memory go run ./cmd/server；适合快速调试，进程退出后状态丢失。
  • API + MongoDBdocker compose up --build；Mongo 8.0 + distroless Go 容器，API 暴露 8080。
  • 前端 Workervinext / Vite 构建到 Cloudflare Worker；Worker 处理应用路由和图片优化，当前 D1、R2 未绑定。

Implemented boundary

不能误判为生产能力的部分

  • CMDB 自动采集使用 StaticSource；主动监控拉取使用硬编码批次。
  • 审批只是状态迁移 API，没有身份认证、外部审批系统或角色授权。
  • DualControl.Execute 返回模拟的 healthy 证据，没有执行真实命令。
  • 异步 RCA 是进程内 goroutine，不具备队列持久化、重试或跨重启恢复。
  • CORS 当前允许任意来源；尚无租户、审计主体、密钥托管和提示注入防护。
  • Mongo 采用单文档 read-modify-replace；互斥锁只覆盖单进程，多 API 副本会有并发覆盖风险。

Verification architecture

测试按边界分层

Go 单元测试覆盖 Loop 上限、CMDB、监控决策、RCA、知识召回和圆桌门禁；API 测试覆盖端点闭环；Mongo integration tag 验证跨连接持久化。前端由 Vitest、构建后 HTML 检查和 Playwright 桌面/移动 E2E 覆盖。
